# 第 2 章 产品定位与业务范围

## 2.1 产品定位

心飞金融是**银行存管模式**的 P2P 网络借贷信息中介平台：借款人发布借款标的，出借人投标获取利息收益，平台收取利差（佣金）与服务费，资金全程由外部银行存管体系托管，平台不接触用户资金。

> 行业背景：P2P 网贷经监管整顿后已基本退出市场，同类业务主流演进形态为持牌消费金融 / 助贷 / 小贷。本平台定位为技术学习与业务验证性质的全功能实现，功能体系对标行业成熟实践构建，便于后续向持牌形态迁移。

## 2.2 业务闭环

````text
注册登录 → 实名认证 → 银行存管开户 → 绑定银行卡 → 充值
                                                    ↓
借款人：发标 → 标的审核 → 募集 → 满标复审 → 放款 → 生成还款计划
                                                        ↓
出借人：投标(预冻结) → 满标 → 放款 → 按期收款 → 提现
                                                        ↓
贷后：到期还款 → 逾期分级 → 催收 → 代偿 → 核销
平台：资金对账 → 差异处理 → 报表统计
````text

> 按**目标服务域**组织。每条需求含：属性 / 用户故事 / 功能描述 / 接口设计 / 数据模型变更 / 验收标准（Given-When-Then）。

## 4.1 账户域（account-service）

### FR-101 注册与登录

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 关联规则 | BR-U01、BR-U04、BR-U06、BR-U07、BR-U08 |

**用户故事**：作为新用户，我希望通过手机号 + 验证码注册并登录，以便使用出借或借款服务。

**功能描述**
- 主流程：输入手机号 → 图形验证码 → 短信验证码 → 校验 → 注册/登录 → 由认证域签发令牌 → 进入首页
- 备选流：① 已注册手机号直接登录；② 账号密码登录（BR-U04）；③ 短信验证码登录
- 异常流：① 验证码错误/过期；② 手机号格式非法；③ 触发失败锁定（BR-U06）；④ 短信服务不可用

**接口设计**

**接口设计**：`POST /my/claims`、`DELETE /my/claims/{claimNo}`、`POST /l/claims/{claimNo}/purchase`、`GET /l/claims`。

**数据模型变更**：启用 `claim_0/1`；`receivable_plan` 增加 `HOLDER_CONSUMER_ID`。

**验收标准**
- AC1：**Given** 持有中的应收计划，**When** 按折价率挂牌，**Then** 债权市场可见。
- AC2：**Given** 他人认购，**Then** 资金划转、持有人变更、手续费扣除。
- AC3：**Given** 转让完成，**Then** 原持有人不再收款，受让人收到。
- AC4：**Given** 已转让债权，**When** 再次挂牌，**Then** 拒绝。

## 4.5 还款域（repayment-service）

### FR-117 还款（支持四种还款方式）

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 关联规则 | BR-R01~BR-R07 |

**用户故事**：作为借款人，我希望按所选方式按期还款；作为出借人，我希望按期收到本息。

**功能描述**
- 主流程：每日 01:00 任务扫描当日到期 → 校验借款人余额 → 存管还款 → 扣减借款人资金 → 按应收计划分配给出借人（扣平台佣金）→ 更新计划状态 → 通知
- 备选流：① 余额不足（转逾期）；② 主动还款
- 异常流：① 部分成功（事务/补偿）；② 通知丢失

**计算公式**

| 方式 | 公式 |
|------|------|
| 一次性还本付息 | 到期应还 = 本金 × (1 + 年利率 × 月数/12) |
| 先息后本 | 每期利息 = 剩余本金 × 年利率/12；末期 = 剩余本金 + 当期利息 |
| 等额本息 | 月供 = 本金 × 月利率 × (1+月利率)^期数 ÷ [(1+月利率)^期数 − 1]；当期利息 = 剩余本金 × 月利率；当期本金 = 月供 − 当期利息 |
| 等额本金 | 每期本金 = 本金 ÷ 期数；当期利息 = 剩余本金 × 月利率；当期应还 = 每期本金 + 当期利息 |

> 末项轧差：末期本金 = 本金 − 前 n−1 期本金之和。

**接口设计**：`POST /l/start-repayment`、`GET /execute-repayment/{date}`、`POST /my/repayments`。

**验收标准**
- AC1：**Given** 选择"等额本金"，**Then** 各期本金相等、利息递减，本息合计 = 本金 + 总利息。
- AC2：**Given** 四种方式分别放款 10000 元/12 期/年化 10%，**Then** 计划数值与独立公式一致（误差 ≤ 0.01 元）。
- AC3：**Given** 到期日余额充足，**Then** 还款成功，计划置已还，出借人收到本息，佣金按 BR-F02 入账。
- AC4：**Given** 余额不足，**Then** 标记逾期并触发 FR-118，不产生部分扣款。
- AC5：**Given** 还款成功但通知丢失，**Then** 补偿后状态一致，不重复扣款。

| 优先级 | P0 |
| 承载服务 | gateway-server + 全部业务服务 |

**用户故事**：作为平台，我需要在网关统一鉴权，并确保每个服务都独立校验令牌，杜绝下游裸奔。

**功能描述**
- 网关层：Spring Security Resource Server 校验 JWT（签名 + 有效期 + 黑名单）→ 按路径做权限控制 → 转发
- 服务层：每个业务服务引入 OAuth2 Resource Server，**本地校验 JWT**，不依赖任何外部透传的用户信息
- 用户上下文：服务内通过 `JwtAuthenticationToken` 直接读取声明，废弃 `jsonToken` query 参数机制
- 内部调用：服务间调用使用客户端凭证令牌或 `token-exchange`，不透传用户令牌

**接口设计**：无新增对外接口；网关路由规则与各服务资源服务器配置见《重构规划文档》专题一。

**数据模型变更**：无。

**验收标准**
- AC1：**Given** 请求携带无效/过期/已吊销 JWT，**When** 经过网关，**Then** 返回 401 且不转发到下游。
- AC2：**Given** 请求绕过网关直连业务服务，**When** 未携带有效 JWT，**Then** 服务返回 401。
- AC3：**Given** 伪造 `jsonToken` 参数直连业务服务，**Then** 服务忽略该参数并返回 401（旧机制已废弃）。
- AC4：**Given** 业务服务需要当前用户信息，**Then** 通过 `Jwt` 声明直接获取，无需解析外部参数。
- AC5：**Given** 服务间内部调用，**Then** 使用独立客户端凭证令牌，权限与用户令牌隔离。

## 4.15 电子合同域（consumer-service 起步，可独立）

### FR-133 电子合同与存证

| 属性 | 值 |
|------|----|
| 优先级 | P1 |
| 承载服务 | consumer-service（一期）→ file-service 存储 + message-service 推送签署 |

- AC4：**Given** 高风险场景，**Then** 触发双录流程并留存音视频证据。

## 4.16 存管对接域（depository-agent-service）

### FR-134 存管指令与异步通知

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 关联规则 | BR-T02、IF-05 |
| 对标 | 行业：资金指令必须签名防篡改、异步通知必须验签 + 幂等、失败必须补偿 |

**用户故事**：作为平台，我需要安全可靠地与外部银行存管系统交互，确保每笔资金指令可追溯、不丢失、不重复。

**功能描述**
- 主流程（指令下行）：业务服务 → 存管代理（参数组装 + 签名）→ 外部存管 → 返回结果 → 记录 `depository_record`
- 主流程（通知上行）：外部存管异步通知 → 存管代理验签 → 幂等校验 → 更新指令状态 → 回调业务服务
- 备选流：① 指令超时未响应 → 主动补偿查询；② 重试（指数退避，最多 N 次）；③ 通知丢失 → 补偿查询兜底
- 异常流：① 验签失败（拒绝并告警）；② 重复通知（幂等返回）；③ 存管不可用（熔断 + 降级提示）

**接口设计**

| 方法 | URL | 说明 |
|------|-----|------|
| POST | `/l/depository/commands` | 下发存管指令（内部） |
| POST | `/gateway` | 接收存管异步通知（params.serviceName 区分业务） |
| GET | `/l/depository/commands/{requestNo}` | 指令状态查询 |
| POST | `/l/depository/commands/{requestNo}/compensate` | 补偿查询 |

**数据模型变更**：`depository_record` 落库持久化（替代仅存 Redis），含 REQUEST_NO、SERVICE_NAME、DIRECTION(IN/OUT)、AMOUNT、STATUS、REQUEST_PAYLOAD、RESPONSE_PAYLOAD、RETRY_COUNT、CREATE_DATE、UPDATE_DATE。

**验收标准**
- AC1：**Given** 任意资金指令，**Then** 落库持久化，可追溯完整请求与响应报文。
- AC2：**Given** 异步通知，**Then** 验签通过才处理，验签失败拒绝并告警。
- AC3：**Given** 同一通知重复推送，**Then** 幂等，不重复执行业务。
- AC4：**Given** 指令超时无响应，**When** 触发补偿查询，**Then** 状态最终一致。
- AC5：**Given** 存管服务不可用，**Then** 熔断生效，业务侧收到明确错误而非挂起。

| 编号 | 规范 |
|------|------|
| IF-01 | 统一响应结构：`{ code, message, result }`，`code = 0` 表示成功，非 0 为业务错误 |
| IF-02 | 错误码统一格式 `E_1xxxxx`，按服务分段：1001xx 公共、1301xx 账户、1401xx 用户、1501xx 交易、1601xx 还款、1701xx 存管代理、1801xx 风控、1901xx 合同 |
| IF-03 | 分页统一参数 `pageNo` / `pageSize`，响应含 `total` 与 `list` |
| IF-04 | 写接口必须支持幂等，幂等键 `REQUEST_NO`（或按资源语义定义的业务唯一键） |
| IF-05 | 对外接口（含存管指令）必须签名校验：参数排序 + 密钥签名 + 时间戳 + 随机数，防篡改防重放 |
| IF-06 | 用户上下文从 JWT 声明获取，**禁止** query 参数透传用户信息 |
| IF-07 | 管理后台接口统一前缀 `/api/v1/`；开放接口前缀 `/l/`；个人中心接口前缀 `/my/` |
| IF-08 | 接口文档用 springdoc-openapi 自动生成，随代码同步更新 |
| IF-09 | 接口版本演进只增不改，废弃接口标注 `@Deprecated` 并保留至少一个版本周期 |
| IF-10 | 长耗时操作（对账、批量）采用异步任务 + 进度查询模式 |

# 第 9 章 验收标准（Definition of Done）

1. 全仓库 `mvn clean test-compile` 通过；
2. 第 4 章全部 P0 需求（FR-101~104、107~108、111、113~115、117~118、120、123、129~130、134）交付，含自动化测试（正常 + 异常场景）；
