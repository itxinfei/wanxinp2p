# 第 1 章 产品定位与行业对标

## 1.1 产品定位

心飞金融是**银行存管模式**的 P2P 网络借贷信息中介平台：借款人在平台发布借款标的，出借人投标获取利息收益，平台收取利差（佣金）与服务费，资金全程由银行存管体系托管，平台不接触用户资金。

> 行业背景说明：P2P 网贷行业经监管整顿后已基本退出市场，当前同类业务的主流演进形态为**持牌消费金融 / 助贷 / 小贷**。本平台定位为技术学习与业务验证性质的全功能实现，其功能体系对标行业成熟实践构建，便于后续向持牌形态迁移。

## 1.2 行业对标分析

对标来源：万信金融（本项目原型功能域）、主流 P2P 系统功能清单、助贷/消费金融"贷前-贷中-贷后"体系、银行委外催收实践、支付对账实践、电子签约合规实践。

|------|----------|----------|

### 1.2.3 逾期催收分级实践（行业）

| 账龄 | 行业策略 | 回款率参考 |
|------|----------|------------|
| M0~M1（≤30 天） | 内部催收：还款日当天/逾期 1/3/7 天短信，第 2/5 天机器人外呼，第 7 天人工介入；提供最低还款、延期选项降低门槛 | 70%~80% |
| M2（31~60 天） | 分层施压：高意愿低能力→协商分期/延期；低意愿高能力→法诉警告/上门；低意愿低能力→委外/准备核销 | 20%~30% |
| M3（61~90 天） | 法诉 + 委外 + 核销准备 | 显著下降 |
| M3+（>90 天） | 委外清收、司法诉讼、核销止损 | 极低 |

> 关键经验：① M1 是回款黄金窗口，投入资源应最重；② 迁徙率（M0→M1、M1→M2、M2→M3）是先行指标，比 M3 不良率更值得监控；③ FPD（首期逾期）客户欺诈概率高，需独立策略。

### 1.2.4 对账体系实践（支付行业）

通用流程三段式：**对账单下载（HTTP/FTP，重试间隔 5~10 分钟）→ 账单解析标准化（XML/Excel/CSV/Text → 统一格式批量入库）→ 轧账/平账**。
以订单号匹配得"交集 + 两个并集"，并集即差异（长款、短款、金额不一致、状态不一致）。
差错处理四手段：**补单、挂账、登账、调账**；跨日切差异通过**滚动补对账**处理。

### 1.2.5 电子合同与合规实践

- 可靠电子签名与手写签名具有同等法律效力；身份核验 + 短信验证 + 实名验证 + 第三方存证形成完整证据链；
- 高风险场景（贷款、担保）需高等级证书 + 音视频双录确认意愿；
- 存证采用"公证前置取证 + 区块链存证"双重背书；全链路数据加密固化保存**不少于证书失效后 5 年**；
- 平台资质：等保三级、ISO 27001、商用密码产品认证；
- 个人信息处理遵循合法、正当、必要原则；人脸等生物特征仅用于比对，不留存原始图像。

## FR-001 用户注册与登录

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 状态 | 待评审 |
| 关联规则 | BR-U01、BR-U04、BR-U06、BR-U07、BR-U08 |

**用户故事**：作为新用户，我希望通过手机号 + 验证码注册并登录平台，以便开始使用出借或借款服务。

**业务价值**：账户体系是所有金融业务的地基；登录安全直接决定资金安全底线。

**功能描述**
- 主流程：输入手机号 → 获取图形验证码 → 获取短信验证码 → 校验 → 注册/登录 → 签发令牌 → 进入首页
- 备选流：① 已注册手机号直接登录；② 账号密码登录（BR-U04）
- 异常流：① 验证码错误/过期；② 手机号格式非法；③ 触发失败锁定（BR-U06）；④ 短信服务不可用（降级提示）

**接口设计**

| 方法 | URL | 说明 |
|------|-----|------|
| POST | `/l/registers` | 手机号注册 |
| POST | `/login` | 账号密码登录（UAA） |
| POST | `/login/sms` | 短信验证码登录（UAA，FR-023） |
| GET | `/sms/{mobile}/key/{key}/code/{code}` | 校验短信验证码（现状已实现） |
| GET | `/login/captcha` | 图形验证码 |

**数据模型变更**：无（复用 `account` / `consumer` 表）。

**前端影响**：`xfjr-front-h5` 登录/注册页、`xfjr-manager` 登录页需接入图形验证码。

**验收标准**
- AC1：**Given** 未注册手机号，**When** 完成验证码校验并提交注册，**Then** 创建账户且返回有效令牌，账户状态为"已注册未实名"。
- AC2：**Given** 已注册手机号，**When** 再次注册，**Then** 返回"手机号已注册"错误（BR-U01）。
- AC3：**Given** 连续 5 次密码错误，**When** 第 6 次尝试登录，**Then** 返回锁定提示且 30 分钟内拒绝登录（BR-U06）。
- AC4：**Given** 验证码已过期（> 5 分钟），**When** 提交登录，**Then** 返回"验证码已失效"（BR-U07）。
- AC5：**Given** 短信渠道不可用，**When** 请求验证码，**Then** 返回明确错误且不创建账户。

## FR-002 实名认证

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 状态 | 待评审 |
| 关联规则 | BR-A01、BR-A04、BR-A05、BR-A06、BR-A07 |
| 对标 | 行业：身份核验 + 短信验证 + 第三方存证形成完整证据链 |

**用户故事**：作为用户，我希望在线完成实名认证，以便获得开户与交易资格；作为运营，我需要核验结果可追溯、可举证。

**业务价值**：实名制是监管硬性要求，也是反欺诈与后续电子合同效力的前提。

**功能描述**
- 主流程：填写姓名 + 身份证号 → 上传身份证正反面 → OCR 识别 → 二/三要素渠道核验 → 返回结果 → 记录落库（含渠道原始响应）
- 备选流：① OCR 置信度低或要素不一致 → 转人工复核（BR-A07）；② 复核通过/驳回
- 异常流：① 渠道超时；② 当日次数超限（BR-A06）；③ 姓名/身份证号格式非法；④ 该身份已绑定其他账户

**接口设计**

| 方法 | URL | 说明 |
|------|-----|------|
| POST | `/l/realnames` | 提交实名认证 |
| GET | `/my/realname` | 查询本人实名状态 |
| GET | `/l/realnames/{userNo}` | 内部查询（开户流程调用） |
| POST | `/l/realnames/{id}/reviews` | 人工复核（运营后台） |

**数据模型变更**：新建 `p2p_consumer.consumer_realname`（ID、CONSUMER_ID、USER_NO、NAME、ID_NUMBER、ID_CARD_FRONT_FILE_ID、ID_CARD_BACK_FILE_ID、CHANNEL、STATUS、FAIL_REASON、CREATE_DATE、CERTIFIED_DATE）。身份证号加密存储。

**前端影响**：新增实名认证页（上传 + 表单）；运营后台新增实名审核页（FR-022）。

**验收标准**
- AC1：**Given** 清晰的身份证正反面，**When** 提交认证，**Then** OCR 正确识别姓名与身份证号，识别准确率 ≥ 95%。
- AC2：**Given** 姓名与身份证号不匹配，**When** 提交，**Then** 返回明确错误码且状态为 FAILED。
- AC3：**Given** 当日已提交 3 次，**When** 第 4 次提交，**Then** 返回次数超限（BR-A06）。
- AC4：**Given** 未实名用户，**When** 调用开户接口，**Then** 返回"未实名"错误（BR-A01）。
- AC5：**Given** 任意一次认证，**Then** 数据库可查到完整记录（时间、渠道、结果、原始响应），身份证号不明文存储。
- AC6：**Given** OCR 置信度低，**When** 提交，**Then** 自动进入人工复核队列（BR-A07）。

## FR-012 还款（支持四种还款方式）

| 属性 | 值 |
|------|----|
| 优先级 | P0 |
| 状态 | 待评审 |
| 关联规则 | BR-R01~BR-R08 |
| 现状 | 仅等额本息实现，其余三种返回 `"-1"`（TR-13） |

**用户故事**：作为借款人，我希望按所选还款方式按期还款；作为出借人，我希望按期收到本息。

**功能描述**
- 主流程：每日 01:00 任务扫描当日到期计划 → 校验借款人余额 → 调用存管还款 → 扣减借款人资金 → 按应收计划分配给各出借人（扣除平台佣金）→ 更新计划状态 → 通知
- 备选流：① 余额不足（标记逾期，转 FR-013）；② 提前还款（BR-R07，二期）
- 异常流：① 还款部分成功（需事务/补偿）；② 通知丢失

**计算公式**（`RepaymentUtil` 统一实现，BigDecimal + ROUND_HALF_UP）

| 方式 | 公式 |
|------|------|
| 一次性还本付息（ALL） | 到期应还 = 本金 × (1 + 年利率 × 月数/12) |
| 先息后本（INTEREST_FIRST） | 每期利息 = 剩余本金 × 年利率/12；末期 = 剩余本金 + 当期利息 |
| 等额本息（FIXED_REPAYMENT） | 月供 = 本金 × 月利率 × (1+月利率)^期数 ÷ [(1+月利率)^期数 − 1]；当期利息 = 剩余本金 × 月利率；当期本金 = 月供 − 当期利息 |
| 等额本金（FIXED_CAPITAL） | 每期本金 = 本金 ÷ 期数；当期利息 = 剩余本金 × 月利率；当期应还 = 每期本金 + 当期利息 |

> 末项轧差：末期本金 = 本金 − 前 n−1 期本金之和，保证本金合计精确等于放款金额。

**接口设计**

| 方法 | URL | 说明 |
|------|-----|------|
| POST | `/l/start-repayment` | 发起还款计划生成（现状） |
| GET | `/execute-repayment/{date}` | 执行当日还款（现状） |
| GET | `/repayment-notify/{date}` | 还款提醒（现状） |
| POST | `/my/repayments` | 借款人主动还款 |

**数据模型变更**：`repayment_plan` / `receivable_plan` 补充 `PRINCIPAL`、`INTEREST`、`COMMISSION` 拆分（现状已有部分字段）。

**验收标准**
- AC1：**Given** 放款时选择"等额本金"，**Then** 生成的还款计划各期本金相等、利息递减，本息合计 = 本金 + 总利息。
- AC2：**Given** 四种还款方式分别放款 10000 元/12 期/年化 10%，**Then** 四种计划数值与独立公式计算一致（误差 ≤ 0.01 元）。
- AC3：**Given** 到期日借款人余额充足，**When** 任务执行，**Then** 还款成功，计划状态置为已还，各出借人收到本息，平台佣金按 BR-F02 入账。
- AC4：**Given** 到期日余额不足，**Then** 计划标记逾期并触发 FR-013，不产生部分扣款。
- AC5：**Given** 还款成功但异步通知丢失，**Then** 补偿查询后状态一致，不重复扣款。

# 第 8 章 实施路线图与估算

> 估算为**粗粒度人天**（1 人天 = 1 人 × 1 工作日），需在参数表确认后细化。

| 阶段 | 目标 | 需求范围 | 估算 | 准出标准 |
|------|------|----------|------|----------|
| 一期 | 安全与事务加固 | TR-01/06/08/09、FR-023、TR-02、TR-05 | 15 人天 | OAuth 密钥不明文；资金接口全部纳入 Seata 且异常回滚测试通过 |
| 二期 | 合规必备 | FR-002（实名）、FR-018（对账）、TR-04、TR-14 | 22 人天 | 实名认证全流程可用；对账任务跑通并产出差异报表 |
| 三期 | 核心链路补全 | FR-012、FR-013、FR-015、FR-016、FR-005/006（记录启用） | 25 人天 | 四种还款方式正确；逾期/代偿/流标闭环可用 |
| 四期 | 运营与性能 | FR-022（后台 + RBAC）、FR-009、FR-021、FR-026、NFR-PRF/TR-03 | 30 人天 | 后台可支撑日常运营；限流生效；电子合同可签可存证 |
| 五期 | 增强 | FR-017、FR-019、FR-020、FR-024、FR-025、FR-027、FR-028 | 22 人天 | 债权转让、会员积分、统计报表、检索、文件、消息、审计上线 |

**关键依赖**：二期依赖一期的安全基线；四期的电子合同依赖二期的对账与三期的放款链路；五期可并行。

**里程碑**：每期结束需完成该期全部 FR 验收标准 + 更新 CHANGELOG + 接口文档。
