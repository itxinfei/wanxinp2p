# 银行存管系统说明（xfjr-depository）

## 定位

`xfjr-depository` 是**外部银行存管系统的模拟实现**，不属于心飞金融业务微服务体系：

- 平台侧只能通过**存管代理**（`xfjr-depository-agent`）以 HTTP 协议访问存管接口，接口即存管协议；
- 平台不接触资金，资金动作由存管系统执行并异步通知；
- 替换为真实银行存管时，只需提供同协议实现并修改 `depository.url`，平台侧代码不动。

## 与主工程的边界

| 项 | 约定 |
|----|------|
| Maven 聚合 | **不在**根 `pom.xml` 的 `<modules>` 内，独立构建 |
| 服务注册 | 不依赖 `spring-cloud-starter-netflix-eureka-client`，不注册业务 Eureka |
| 数据库 | 独立库 `p2p_bank_depository`（见 `docs/sql/p2p_sql/xfjr-depository-init.sql`） |
| 端口 | 独立端口，由 Apollo `xfjr-depository` 应用 `application` 命名空间下发；本地默认值见该命名空间 |
| 调用方 | 仅 `xfjr-depository-agent`，通过 Apollo 配置项 `depository.url` 指向存管地址 |
| 耦合 | 编译期仅依赖 `xfjr-common`；首次构建前需先 `mvn install -pl xfjr-common` |

## 构建与启动

```bash
# 1. 首次或 common 变更后，先把公共模块装入本地仓库
mvn install -pl xfjr-common -DskipTests

# 2. 独立构建存管系统
mvn install -f xfjr-depository/pom.xml -DskipTests

# 3. 启动（Apollo 指向独立环境，勿与业务服务共用命名空间）
java -jar xfjr-depository/target/xfjr-depository-1.0-SNAPSHOT.jar \
  --apollo.meta=http://192.168.20.88:28080
```

## 存管代理侧配置

`xfjr-depository-agent` 读取 Apollo 键 `depository.url` 作为存管基地址（如 `http://<存管主机>:<端口>`）。未配置时下发指令会抛 `E_160104`（存管服务地址未配置）。

## 迁移到真实存管

1. 按银行协议实现存管接口（账户、绑卡、指令、回调验签）；
2. Apollo 将 `depository.url` 指向真实存管；
3. 关闭模拟系统；
4. 回调验签密钥独立于业务 JWT，不与 `xfjr.jwt.key-path` 混用。
